# 使用 OAAM

[English](USAGE.md) · [简体中文](USAGE.zh-CN.md) · [日本語](USAGE.ja.md) · [Deutsch](USAGE.de.md) · [README](README.zh-CN.md)

本文介绍桌面界面的操作。本次源码快照不附带预构建程序；当前交付与发行目录要求见
[构建与测试](BUILD.zh-CN.md)。

## 首次导入

1. 选择允许 OAAM 检查的工具和环境。需要 WSL 时先启动对应发行版，再明确选择它；发现环境不等于授权扫描。
2. 选择项目或全局资产库，检查来源并选择正确的工具入口。同一物理来源的 CLI 与 App 解释可能不同。
3. 审查资产及资源后导入。保存的 Version 与实时来源分别管理。
4. 选择版本，检查可用位置。审查现有文件、完整预期文件图、转换及必要授权，确认后再应用。
5. 后续刷新使用状态以发现外部修改，再决定保留、修复或接纳为新版本。备份中的基线不会默默接纳后来的工具修改。

## 管理资产和项目

版本保留内容与完整原生资源，资产可编辑的显示信息与之独立。分享前检查导出内容：资产归档、
支持包和性能追踪用途不同。已保存授权可在对应资产中查看和撤销。

项目的重命名、改绑、停止管理和恢复作用于项目身份及管理状态。改绑项目不会移动或覆盖既有
部署文件；继续操作前审查仍保留的旧位置。

## 备份与恢复

在依赖破坏性生命周期操作前创建并检查完整状态备份。恢复需要明确审查，并以整体状态切换，
不会拼接任意数据库片段。数据库缺失时，恢复界面可以检查所选备份并执行恢复。返回普通界面后，
刷新受管位置，用恢复的基线检查外部变化。

## 已知限制

- 能力按工具入口、资产种类、方向、平台与版本区分，以具体分析结果为准。无法支持的调用或私有语义
  可能阻断转换；应保留来源，不要为了通过操作而删除有意义的字段。
- 某些明确不支持的 Workflow 结果仍使用临时失败、重试的通用说明。
- 项目改绑后的旧部署提示可能出现在全局资产库，主体不准确。
- 恢复成功后，Host 替换可能丢失持续显示的完成提示。请核对恢复后的状态并刷新使用情况，
  不要仅因提示消失就反复恢复。
- 恢复专用入口仍有引用未显示备份清单的次要文案。
- 操作流程仍较复杂，延迟会波动。代表测试不能证明未验证的工具、平台、语言及显示组合；
  当前不承诺由 watcher 驱动的后台同步。

转换与部署的设计原理见[技术介绍](ARCHITECTURE.zh-CN.md)。
