# OAAM の使い方

[English](USAGE.md) · [简体中文](USAGE.zh-CN.md) · [日本語](USAGE.ja.md) · [Deutsch](USAGE.de.md) · [README](README.ja.md)

デスクトップ画面の操作を説明します。このソーススナップショットにはビルド済みの実行ファイルは含まれません。
現在の起動方法と配布要件は[ビルドとテスト](BUILD.ja.md)、設計の背景は[技術紹介](ARCHITECTURE.ja.md)を参照してください。

## 最初の取り込み

1. OAAM に調査を許可するツールと環境を選びます。WSL が必要なら先に対象のディストリビューションを起動し、明示的に選択します。環境の発見だけではスキャンを許可したことになりません。
2. プロジェクトまたはグローバルライブラリを選び、利用できるソースと対象ツールの入口を確認します。同じ場所でも CLI と App で解釈が異なる場合があります。
3. アセットと関連リソースを確認して取り込みます。保存した Version は、現在のソースとは別に管理されます。
4. Version を選び、利用できる場所を確認します。既存ファイル、変更後の完全なファイル構造、変換内容、必要な承認を確認したうえで適用します。
5. 後から利用状況を更新し、外部の変更を検出します。保持、修復、新しい Version としての取り込みを検討します。バックアップに保存された基準へ、その後のツール側の変更が自動で取り込まれることはありません。

## アセットとプロジェクトの管理

Version は内容と完全なネイティブリソースを保持します。アセットの編集可能な表示情報は別に管理されます。
共有する前にエクスポート内容を確認してください。アセットのアーカイブ、サポートバンドル、性能トレースは用途が異なります。
保存済みの承認は、対象アセットで確認して取り消せます。

プロジェクトの名前変更、フォルダーの再設定、管理の停止と復帰は、プロジェクトの識別情報と管理状態に作用します。
フォルダーを再設定しても、配置済みのファイルは移動も上書きもされません。残っている場所を確認してから操作を続けてください。

## バックアップと復元

破壊的なライフサイクル操作に備え、状態全体のバックアップを作成して内容を確認します。復元には明示的な確認が必要で、
状態を一つのまとまりとして置き換えます。任意のデータベース断片を結合する処理ではありません。データベースがない場合も、
復元画面から選択したバックアップを調べて復元できます。通常画面に戻ったら管理対象の場所を更新し、復元した基準と外部の変更を比較します。

## 既知の制限

- 対応範囲はツールの入口、アセットの種類、操作の方向、OS、ビルドごとに異なります。画面の分析結果を確認してください。対応できない呼び出し方式や独自の意味が変換を阻む場合があります。有意なフィールドを削除して操作を通すのではなく、元の情報を保持してください。
- 明確に未対応の Workflow に対して、一時的な失敗や再試行を示す文言が表示される場合があります。
- プロジェクトのフォルダー再設定後、残った配置先の通知がグローバルライブラリに誤った対象名で表示されることがあります。
- 復元成功後の Host 置き換えで、継続表示される完了通知が失われる場合があります。復元された状態を調べて利用状況を更新し、通知が消えただけで復元を繰り返さないでください。
- 復元専用の画面には、表示されていないバックアップ一覧に言及する軽微な文言の問題があります。
- 操作はまだ複雑で、応答時間にもばらつきがあります。代表的なテストだけで、未検証のツール・OS・言語・画面の組み合わせを保証することはできません。watcher によるバックグラウンド同期も現在は提供していません。
